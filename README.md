## 1. System Overview & Core Principles

BitElevate PR Review Copilot assists senior engineering mentors by automatically performing first-pass code reviews on pull requests submitted daily by engineering interns. 

### Core Architectural Guarantees:
1. **Mandatory Human-in-the-Loop Gate**:
   - **Zero unapproved AI comments reach an intern or GitHub.**
   - Every observation generated by AI starts in a `PENDING_APPROVAL` status and must be explicitly approved, edited, or rejected by a human mentor.
2. **Defensive Containment Envelope**:
   - Untrusted PR diffs and markdown descriptions are wrapped within `<untrusted_pr_diff>` XML boundary tags.
   - Malicious closing tags (`</untrusted_pr_diff>`) in intern code are neutralized into `&lt;/untrusted_pr_diff&gt;` prior to prompt delivery, neutralizing indirect prompt injection attacks.
3. **Verbatim Evidence Verification (`verify_evidence`)**:
   - Any AI finding whose `evidence_quote` does not appear verbatim in the pull request diff (normalized for whitespace) is automatically dropped, preventing LLM hallucinations.
4. **Structured Schema Adherence & Repair Retries**:
   - LLM responses are strictly validated against Pydantic v2 models.
   - If a provider returns malformed JSON, an automatic repair retry is triggered before safely failing.
5. **Safe Error Handling**:
   - Centralized exception handlers intercept all errors and return uniform JSON payloads with a correlation `error_id`.
   - Never leaks internal stack traces, database schema, or local file system paths to clients.

## 2. Technology Stack

- **Backend Framework**: Python 3.11+, FastAPI, Starlette
- **Data Validation & Settings**: Pydantic v2, Pydantic-Settings
- **ORM & Persistence**: SQLAlchemy 2 (synchronous engine), SQLite (`PRAGMA foreign_keys=ON;`)
- **HTTP Client**: HTTPX (async client with connection pooling and mock transports)
- **AI Integrations**: OpenAI-compatible adapter (`gpt-4o-mini`, `gemini-1.5-flash`), Mock deterministic reviewer
- **Testing & Quality Assurance**: Pytest (53 automated tests), Ruff (linter/formatter), Mypy (static typing), Bandit (AST security analysis), Pip-Audit (dependency vulnerability scanner)

## 3. Quickstart Guide

### Prerequisites
- Python 3.11+
- Git
- PowerShell (Windows) or Make (Linux/macOS)

### Local Setup
```powershell
# Clone repository
git clone https://github.com/Neminath-jain/CynbitAsess.git
cd CynbitAsess

# Create and activate virtual environment
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# Install dependencies
pip install -r backend/requirements.txt
```

### Environment Configuration
Copy `.env.example` to `.env`:
```powershell
cp .env.example .env
```

Key environment variables:
- `APP_ENV`: `development`, `testing`, or `production`
- `DATABASE_URL`: SQLite or PostgreSQL database connection string (default: `sqlite:///./bitelevate_copilot.db`)
- `MENTOR_TOKEN`: Secret token required for mentor triage actions (default: `test-mentor-token`)
- `LLM_PROVIDER`: `mock` (offline deterministic rule reviewer) or `openai`
- `LLM_API_KEY`: API key for live provider (when using `openai`)
- `LLM_MODEL`: Active model name (e.g. `gpt-4o-mini`)

## 4. Running the Application

### Using PowerShell Helper (`run.ps1`)
```powershell
# Run the test suite (53 tests)
.\run.ps1 test

# Run linter and type checker (Ruff + Mypy)
.\run.ps1 lint

# Run security scans (Bandit + Pip-Audit)
.\run.ps1 audit

# Run evaluation benchmark suite (10 diffs)
.\run.ps1 eval

# Launch the FastAPI development server
.\run.ps1 run-api
```

### Using Makefile (Linux / macOS)
```bash
make test    # Run pytest
make lint    # Run ruff check & mypy
make audit   # Run bandit & pip-audit
make eval    # Run evals benchmark runner
make run-api # Launch uvicorn server
```

The interactive Swagger documentation will be available at:  
👉 **http://localhost:8000/docs**

## 6. API Reference

| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| `GET` | `/health` | Service health status and environment check | No |
| `POST` | `/api/v1/reviews` | Trigger end-to-end PR review ingestion & AI analysis | No |
| `GET` | `/api/v1/reviews` | List past pull request reviews with status filtering | No |
| `GET` | `/api/v1/reviews/{id}` | Retrieve complete review details with findings | No |
| `POST` | `/api/v1/findings/{id}/decision` | Submit mentor triage decision (`APPROVE`, `EDIT`, `REJECT`) | **Mentor Token** (`X-Mentor-Token`) |
| `GET` | `/api/v1/reviews/{id}/export` | Export mentor-approved review comments as Markdown | **Mentor Token** (`X-Mentor-Token`) |

### Example: Reviewing a PR and Triaging Findings

#### 1. Submit PR for Review
```bash
curl -X POST http://localhost:8000/api/v1/reviews \
  -H "Content-Type: application/json" \
  -d '{"pr_url": "https://github.com/cynbit/bitelevate-sample/pull/42"}'
```

#### 2. Mentor Approves or Edits a Finding
```bash
curl -X POST http://localhost:8000/api/v1/findings/<FINDING_UUID>/decision \
  -H "Content-Type: application/json" \
  -H "X-Mentor-Token: test-mentor-token" \
  -d '{
    "action": "EDIT",
    "mentor_notes": "Well spotted. Adding index suggestion for intern.",
    "edited_explanation": "Intern: Please index the foreign key to avoid full table scans.",
    "edited_suggested_fix": "CREATE INDEX idx_user_id ON orders(user_id);"
  }'
```

#### 3. Export Approved Comments as Markdown
```bash
curl -X GET http://localhost:8000/api/v1/reviews/<REVIEW_UUID>/export \
  -H "X-Mentor-Token: test-mentor-token"
```

## 7. Evaluation Benchmark Suite (`evals/`)

The evaluation harness validates detection accuracy and adversarial injection resistance across a corpus of 10 synthetic diffs:

- **Planted Defects (4)**: Missing FK index (`PERF_MISSING_FK_INDEX`), hardcoded credentials (`SEC_HARDCODED_SECRET`), unverified JWT decode (`SEC_JWT_UNVERIFIED`), missing unit tests (`TEST_MISSING_UNIT_TESTS`).
- **Clean Baselines (3)**: Indexed FK, verified JWT, environment configuration with unit tests.
- **Prompt Injection Attacks (3)**: XML breakout tags (`</untrusted_pr_diff>`), system instruction override comments, markdown code fence traps.
